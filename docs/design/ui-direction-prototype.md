# YoPet 首页方向原型（仅设计研究）

> 状态：待评审。此文件和 `lib/features/home/ui_direction_prototype.dart`
> 只存在于 `codex/ui-direction-prototype` 分支，不是 F6 的生产实现。

## 要回答的问题

哪一种首页结构能让首次养鱼的城市用户，在 5 分钟空档里愿意停留，
并自然完成“领养第一条鱼”？

这不是配色投票。三种方案分别验证不同的信息层级和第一操作：

| 方案 | 名称 | 先给用户什么 | 主操作 | 应观察的反馈 |
| --- | --- | --- | --- | --- |
| A | 沉浸鱼缸 | 鱼缸本身 | 领养一条 | 是否想停下来观看，而不是寻找功能 |
| B | 鱼的肖像馆 | 单条鱼的角色与状态 | 打开鱼详情 | 是否觉得鱼有性格、值得命名和照料 |
| C | 安静的每日仪式 | 一句可感知的每日变化 | 走进鱼缸 | 是否给了用户每天回来一次的自然理由 |

所有方案暂用同一条“简笔轮廓 + 水彩填色 + 克制科技轨迹”的程序化金鱼，
从而把评审焦点放在 UI 结构而非单张鱼素材。

## 如何运行

在项目根目录执行：

```powershell
flutter run -d windows --route "/prototype/ui-direction?variant=A"
```

也可以把 `A` 改为 `B` 或 `C`。开发环境中，页面底部的研究切换条支持按钮和
键盘左右方向键切换；生产构建隐藏该切换条，且不允许绕过正常登录流程。

## 评审方式

每看完一个方案，只需回答以下三句中的任意一句：

- “我愿意每天打开的是 A/B/C，因为…… ”
- “保留 A 的……，换成 B/C 的…… ”
- “我不喜欢……，它让我感觉…… ”

我会将反馈记录成明确的设计决策，再重新用生产级组件实现赢家，而不会把此原型代码直接合入 F6。
